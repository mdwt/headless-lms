`@headless-lms/content-plate` is the [Plate](https://platejs.org)-based implementation of the swappable activity content editor. It default-exports an `EditorModule` satisfying `@headless-lms/editor`; the content blob is the Plate node array, stored opaquely by the backend — the server never interprets it.

## What's included

- **Text blocks** — paragraphs, headings, blockquote, code blocks with syntax highlighting, bulleted/numbered/to-do lists, toggle, callout, columns, tables, dates, emoji, links, font and background color.
- **Media** — image, video, audio, file and URL embeds, with captions, resize, preview, and upload placeholders (uploads go through the [storage adapter](/docs/adapters/storage/minio)'s presigned URLs).
- **Notion-style UX** — `/` slash command menu, drag handles and drop targets, multi-block selection, right-click block context menu (turn into, color, align, duplicate, delete), floating formatting toolbar, and autoformat shortcuts (`#`, `>`, ` ``` `, `-`, …).
- **Host slots** — given a `toolbar` slot, a fixed toolbar that switches between text formatting and media options for the selected block replaces the floating one; given a `blocks` slot, a block library where blocks are clicked in at the cursor or dragged onto the page.

## Swapping the editor

The editor is behind `@headless-lms/editor`: an `EditorModule` bundles the client-side `Editor`, an RSC-safe `Renderer`, an optional `validate` function, a required `assetIds` function, and `meta: { type, version }` identifying the content format. Implement the contract and register your module in the frontend to replace Plate entirely — existing content keeps working as long as your module declares the format it can render.

`assetIds(config)` is a pure function that returns the ids of the media library files a config shows: every image, video, audio or file node that names a host asset. When an activity is saved, the admin sends these ids as the activity's asset links, together with any links the activity already has that the editor does not manage. The server accepts only ready files from the org's media library and refuses the save, naming the ids, otherwise. An editor that embeds no host assets returns `[]`. The Plate editor collects every node's `assetId`.

The API returns each activity with `assetUrls`: a signed URL for every file the activity links, keyed by asset id. The host passes that map to the `Editor` and to the `Renderer` as `assetUrls`, and a media node that names a host asset shows the URL from the map instead of the `url` stored in the config, which was only valid when the content was saved. Only linked files get a URL, so a file the editor shows but `assetIds` leaves out never reaches students. The URLs expire: a player that outlives one calls the `MediaProvider`'s `refreshUrl`, and the host answers by reading the activity again.

A host that lays out the editing screen itself passes `slots` to the `Editor`: DOM elements for the `toolbar` and the `blocks` library. An editor lists the slots it fills in `EditorModule.slots`, and the admin shows the matching toolbar and Blocks panel only for those.
