`@headless-lms/content-plate` is the [Plate](https://platejs.org)-based implementation of the swappable activity content editor. It default-exports an `EditorModule` satisfying `@headless-lms/editor`; the content blob is the Plate node array, stored opaquely by the backend — the server never interprets it.

## What's included

- **Text blocks** — paragraphs, headings, blockquote, code blocks with syntax highlighting, bulleted/numbered/to-do lists, toggle, callout, columns, tables, dates, emoji, links, font and background color.
- **Media** — image, video, audio, file and URL embeds, with captions, resize, preview, and upload placeholders (uploads go through the [storage adapter](/docs/adapters/storage/minio)'s presigned URLs).
- **Notion-style UX** — `/` slash command menu, drag handles and drop targets, multi-block selection, right-click block context menu (turn into, color, align, duplicate, delete), floating formatting toolbar, and autoformat shortcuts (`#`, `>`, ` ``` `, `-`, …).
- **Host slots** — given a `toolbar` slot, a fixed toolbar that switches between text formatting and media options for the selected block replaces the floating one; given a `blocks` slot, a block library where blocks are clicked in at the cursor or dragged onto the page.

## Swapping the editor

The editor is behind `@headless-lms/editor`: an `EditorModule` bundles the client-side `Editor`, an RSC-safe `Renderer`, a `validate` function, and `meta: { type, version }` identifying the content format. Implement the contract and register your module in the frontend to replace Plate entirely — existing content keeps working as long as your module declares the format it can render.

A host that lays out the editing screen itself passes `slots` to the `Editor`: DOM elements for the `toolbar` and the `blocks` library. An editor lists the slots it fills in `EditorModule.slots`, and the admin shows the matching toolbar and Blocks panel only for those.
